# 网页页面管理

在 Markdown 头部加入 `addons: [slide-sorter]`。工作区已为现有汇报和新建骨架启用。

开发服务底部工具栏的“排序”打开缩略图面板。拖到目标缩略图左半侧表示插到前面，右半侧表示插到后面，松手后自动保存。也可使用“前移”和“后移”。保存完成后显示“已保存到 Markdown”，播放中的内容会跟随新的页码。关闭面板继续播放；刷新后页序仍保留。

点击缩略图选中插入位置，再点击“＋ 新增页”，会在其后插入一张小字体、双栏、标题和正文均可拖拽的新页。新页骨架统一维护在 `templates/new-slide.md`；正文、公式和拖拽坐标写入当前 talk 的 Markdown。新增后关闭面板，就可以在网页侧边编辑器中继续写作。要保留致谢在最后，选中致谢的前一页再新增。

每张内容页下有“复制页”和“删除页”。复制将完整页头、正文、公式、备注、布局及拖拽坐标复制到下一页；图片和 Draw.io 的素材引用保持相同，若希望编辑图形互不影响，需要另存一份素材并修改引用。删除会先显示页码和标题确认，可取消。所有增删和复制同样自动保存并备份；删掉正在播放的页面后显示后继页，若删除的是最后一页则显示前一页。

Slidev 52.19.1 在页数变化后可能复用旧的页面模块。工作区的 `scripts/patch-slidev-editor.mjs` 版本补丁在 Slidev 读取新文件后清理模块缓存并自动刷新，随后恢复管理面板和选中页；刷新期间不重发保存请求。这样新增、删除、复制后，缩略图和网页编辑器使用同一份最新内容。

首张封面的 frontmatter 是整份汇报的全局配置，因此固定在首位，不能删除或复制。其余页面均可移动，包括致谢页。当前插件面向每个 talk 的单文件 `slides.md`；含 `src:` 导入、隐藏或禁用页面时会明确提示改用 Markdown，以免把源文件序号和播放序号混淆。

换序和复制保留完整的源文件区块，保留公式、备注、布局和 `dragPos`。首张配置不改写。每次修改前在本汇报 `.slide-order-history/` 备份原稿；外部文件版本发生变化时拒绝覆盖，点击“重新加载”后再排序。请求失败可重试，超时建议重新加载确认文件状态。

界面采用 Slidev 的 `custom-nav-controls.vue` 扩展点和原生缩略图组件。写入接口 `/__slide_order` 仅在开发服务存在，只接受当前来源，按完整页面 ID 排列或指定页面的增删/复制操作保存；客户端不能指定文件路径。静态构建与打印不显示排序入口。

启动仍使用各汇报的 `./start.sh`。新增插件或修改头部 addons 后需要重启。验证命令：在工作区根目录执行 `npm run check:sorter`。

参考：[Slidev 全局层与导航扩展](https://sli.dev/features/global-layers)。


自动测试覆盖原始区块与 CRLF 保留、重复页、无末尾换行、封面保护、增删复制、备份及版本冲突。网页回归请对过滤汇报的独立副本启动服务，再运行：

SLIDEV_TEST_FILE=/absolute/path/to/test-talk/slides.md \
