# Markdown 写作与可视化排版工作流

## 把页面分成两类

普通页直接写标题，列表，公式与表格。两栏使用模板的 `columns` 容器。统一字号与页边距由 CSS 管理，无需为每段文字提供坐标。

需要精确图文关系的页面，再把图，关键公式，说明分别包在 `v-drag` 内。一个块只承担一种内容，以便单独移动。当前六页密集正文按用户的拖拽优先偏好，将标题和各内容块分别放入 `v-drag`；页码仍由母版自动管理。

图内的坐标轴与图例应在绘图工具里调整。拖动 SVG 图片只会移动或缩放整张图，不会使图内各元素成为 Slidev 对象。

## 可直接复制的片段

```md
---
section: 方法说明
dragPos:
  equation: 90,170,420,120,0
  explanation: 550,180,330,150,0
---

# 方法中的关键公式

<v-drag pos="equation" class="drag-block">

$$
\pi^N=\sum_{i=1}^N w_i\delta_{x_i}.
$$

</v-drag>

<v-drag pos="explanation" class="drag-block note">

这里填写对公式的解释。

- 符号含义
- 适用条件

</v-drag>
```

`dragPos` 五项依次是左，上，宽，高，旋转角。前四项使用画布坐标，最后一项为度数。模板画布宽 980，比例 16:9，高约 551.25；浏览器缩放时坐标仍以画布为准。

`pos` 使用有意义的名称。同页不能有两个块共用同一位置名；不同页面可以复用名称。删除块时也清理对应坐标。组件标签与 Markdown 内容之间保留空行，便于正确解析段落与公式。

官方也支持把坐标直接放进标签，但那会混合内容与布局。模板统一使用 frontmatter，不依赖内联坐标的正则替换路径。[官方语法](https://sli.dev/features/draggable)

## 每次排版的顺序

- 先写出这一页要讲什么，删去与主旨无关的文字。
- 为图选择足够宽的区域。先调整宽度，再确认标题和图例可读。
- 双击需要调整的块，拖动外框区域移动，拖角点缩放，拖上方手柄旋转。Shift 配合角点缩放可保持比例。
- 点击空白处结束操作。观察源文件坐标变化后再切换编辑工具。
- 回看整页，尤其检查标题与页脚之间的可用区域。

固定高度并不会自动把文字缩小到框里。增加文字后可能需要增加高度，改宽度，删减内容或拆页。缩放外框主要改变容器尺寸，字体仍由 CSS 决定。图片本身使用 `width: 100%; height: auto` 保持比例，因此图片的可见高度可能不同于手动指定的框高。

自动高度的高级用法可参考官方文档。当前模板为便于拖角点调整，使用固定高度；不把未测试的自动高度当作默认约定。

## 当前版本的必要修补

模板会在 `npm ci` 后自动执行 `scripts/patch-slidev-editor.mjs`，修复 52.19.1 中拖拽后侧栏读到旧坐标的问题。保留整个 `scripts/` 文件夹，不要忽略安装脚本。补丁具体原因与复现值见 `FINDINGS.md`。

未经修补的原版不能保证“拖拽后立刻在侧栏改字”保留新位置，刷新页面也不足以避免本轮复现的问题。当前模板已修补并验证这条流程。升级 Slidev 前需运行回归检查，不要简单删除版本校验。

## 保存与回退

编辑必须连接 `npm run dev` 启动的开发服务。本轮检查的原生保存器具有约 500 ms 防抖，停止操作后至少稍等一下，不要立即关服务。实际等待取决于机器与文件系统，源文件已更新才是保存依据。

浏览器侧栏编辑器与 VS Code 都会写同一份 Markdown。避免一边在 VS Code 保留未保存旧版本，一边拖拽，再用旧版本覆盖新坐标。模板关闭了保存时格式化，但没有修改仓库级设置。

当前没有把原生拖拽撤销历史作为保证。一次布局满意后保存快照或提交 Git，发生误拖时可以恢复相应 `dragPos`。

当前仓库将 `.agents/.tmp/` 当作临时工作区使用，文件可能不被 Git 跟踪。长期沉淀时，应把模板复制到正常跟踪的项目目录，或明确调整跟踪策略，再执行版本管理。

## 排版与素材约定

起步模板正文 24 px，标题 36 px，封面标题 48 px，说明 20 px。当前汇报的六页双栏正文使用 `research-slide`：正文 17 px，分块标题 20 px，页面标题 30 px，紧凑说明 15.5 px，表格 15 px。画布上 1 px 不等于 PowerPoint 的 1 pt。字号是本模板的设计起点，内容增加时先拆页，避免无限压缩。

主色与文本颜色在 `styles/academic.css` 顶部。页脚文本来自每页的 `section`，页码自动生成。标题太长时允许合理换行，并检查是否挤占正文。

中文使用本地字体栈，避免演示时下载在线字体。跨机器若缺少 Noto Sans CJK SC，会尝试微软雅黑等回退字体，字形和换行可能变化。换演示机器后重新检查，PDF 是稳定备份。

图片放入 `public/`，通过 `/文件名.svg` 或 `/文件名.png` 引用。公式继续用 LaTeX 写在 Markdown 中。讲者备注放在页尾 HTML 注释内。

## 导出与演示

```bash
npm run build
npm run export:pdf
npm run export:pptx
```

静态构建写入 `dist/`，PDF 与 PPTX 写入 `output/`。这些命令在本地生成文件，不自动发布到外网。`npm run build:starter` 单独检查起步模板，输出到 `dist-starter/`。

`npm run dev:starter` 使用 `starter.md`，但默认导出命令仍使用 `slides.md`。如需导出起步文件，运行 `node scripts/slidev.mjs export starter.md --output output/starter.pdf`，或在新项目中把起步内容复制为 `slides.md`。

PPTX 导出显式关闭 `with-clicks`，避免以后增加分步动画时意外把一步变成一页。导出结果为每页图片，原文和公式的可编辑源仍然是 Markdown。浏览器演示保留交互，PDF 适合阅读与现场备份，PPTX 适合要求该扩展名的播放环境。[官方导出说明](https://sli.dev/guide/exporting)

静态站点和导出文件没有开发服务的源文件写回能力。对外展示时不要把它们当作远程排版编辑器。
