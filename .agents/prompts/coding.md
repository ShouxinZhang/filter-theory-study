语言设置: 全程优先使用中文，例如各类plan/log/report/skills，除非特别指定，否则不要使用其它语言。

# 时刻牢记的第一性准则:

- 任何时候都必须将模块化，层次化思想应用起来。善于利用tree或者graph结构. 主干文件绝对不能臃肿, 能拆分到子模块的就到子模块里。例如SKILL书写时，尽可能将模板等冗长细节放到references或者scripts子文件夹里; 又比如软件模块，不管是python, ts之类，都应该时刻注意，不要把太多功能堆放在单个文件里, 而是拆分为有层次的多子文件夹结构
- 任何时候，都应该保持精简的回答风格, 能用5行以内描述的，绝对不要用20行以上描述

# 上下文工程技巧:

- PLAN地图技巧, 完成长程任务的时候, 需要制作一个带有打勾框的层次地图, 按照地图持续推进打勾. 如果计划本身有问题, 可以修改计划后继续.

# 代码创作上的方法论:

- 善于高效利用CPU, GPU, 内存. 利用并行等各种方法加速
- 涉及到模型训练或者类似长时间代码任务的时候，需要设计好check point等机制，随时继续
- 创作通用性, 可复用性强的优雅代码, 在代码构筑完成后必须重新审阅一次进行精修, 多次创建的重复变量, 类, 函数等 需要重构, 冗余无用的代码需要删除.
- 注重利用重复资源, 例如.venv环境, 必须检查是否有共享环境可以使用, 防止浪费磁盘资源.
- 代码文件, 必须书写注释, 没有注释的代码是灾难性的

# 长时间工作的方法论:

- 长期工作同一任务会导致同一叶子目录中产生大量文件, 需要阶段性在每轮工作的收尾或者其它合适的时间进行整理, 保持每个目录的清晰和可管理性.
- 长时间工作经常会遇到一直难以改进的bug或者问题, 此时, 你应该将问题发送给2-3个无记忆agent, 询问问题出现在了哪里，并根据建议更新计划
- 对于每个任务，记得log，为子任务写log报告是良好习惯
