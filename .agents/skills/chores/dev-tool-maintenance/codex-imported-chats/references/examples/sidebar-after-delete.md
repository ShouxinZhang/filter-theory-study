# 已删除的 Claude 对话仍显示在 Codex 项目侧栏

2026 年 11 月的一次 Linux 桌面端排障中，用户确认删除 12 个 Claude 导入副本，其中 2 个已归档。本地 Codex CLI 版本为 0.162.1。删除接口对 12 个 ID 都返回成功，活动及归档记录和对应的会话文件也已移除。用户随后在原窗口仍看到一条具名对话和三条开头相同的论文对话。

| 当时核对的位置 | 得到的证据 |
| --- | --- |
| `~/.codex/external_agent_session_imports.json` 的 `records` | `source_path` 指向 Claude 原记录，`imported_thread_id` 标识 Codex 副本。导入历史在删除后仍保留。 |
| `~/.codex/state_5.sqlite` 的 `threads` | 12 个目标 ID 均已消失。复查会话文件时也检查了归档目录和压缩的 `.jsonl.zst`。 |
| `~/.codex/sqlite/codex.db` 的 `local_thread_catalog` | 本地主机仍有 10 条目标记录。三个相似标题各自对应不同 ID，桌面侧栏显示的标题也可能取自首条消息。 |
| 原窗口与新窗口的同一项目 | 索引清理后，旧窗口仍短暂显示旧标题。新窗口回到原项目后，该批条目已消失。 |

## 本次修复的边界

先用只读查询求出三个集合的交集：用户确认的 ID、后端已经删除的 ID、桌面目录仍列出的同一主机 ID。若界面刷新或桌面端自身的索引重建能解决问题，到此即可结束。

本例确认存在残留后，才对桌面目录执行定向事务。按 `host_id` 和完整 `thread_id` 删除交集中的 10 行，按该版本的实现递增 `local_thread_catalog_metadata.catalog_revision`，校验其他目录项的主机和 ID 集合一致后提交。复用此办法前，先检查本机实际 schema、目录修订机制和主机标识。没有匹配的行时，继续查窗口缓存或同名对话。

最后在新窗口打开原项目和原聊天，目视核对用户截图中的标题。9 个可访问的 Claude 源文件在删除前后的内容哈希一致，另 3 个源路径在操作前已经缺失。
