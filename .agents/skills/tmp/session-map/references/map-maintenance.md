# 讨论树维护约定

## 用户与 agent 的分工

维护目标是帮助用户表达和回顾自己的思路。相信用户能够审核主题组织、重点和措辞，agent 先交付可编辑的整理结果，再根据用户修改与反馈迭代。

用户要求维护时，直接开展合理的草稿编辑。延续原图结构并保留用户备注，将已讨论、已决定、已实现、已验证、待验证和暂缓事项按实际证据区分，具体分组随讨论内容调整。

## 按信息缺口读取

- 当前上下文完整时，直接依据已有对话整理主题与结论。现有 `map.md` 按编辑需要读取，避免覆盖用户在文件中的修改。
- 需要定位引用时，先提取精简轮次索引或锚点，工具返回内容限于需要的编号与标题。
- 上下文发生压缩后，先使用仍可见的摘要和现有讨论树。缺失旧细节或对某个结论有疑问时，定点读取对应轮次的必要片段。
- 读取范围由具体问题决定。完整重读 `prompts.md` 或源日志会重复占用上下文窗口，默认维护流程采用增量、局部查证。

## 编辑与交付

- 按主题组织主线和支线，简要记录问题、结论、关键决定和未决事项，用 `[pN](prompts.md#pN)` 关联原文。
- 对已改变的决定同步修订状态，保留关键来源。将证据不足的事项标为待验证，将用户决定延后的事项标为暂缓。
- 每次围绕新增讨论与用户反馈更新，保持图的可读性，避免把工具输出和整段原文搬入图中。
- 写入后检查本次引用的锚点和文件链接，检查所用编号时仅返回必要的匹配结果。
- 使用 `get_model_name.py --header` 更新本次维护署名，交付 `map.md` 链接和简短说明。

`prompts.md` 由同步脚本维护，`map.md` 的主题组织由用户与 agent 协作维护。两者的更新节奏可以独立。
