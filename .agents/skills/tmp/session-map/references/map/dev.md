# 开发任务

输出：`.agents/.tmp/session/<id>/map/dev/<任务>.md`。

## 目的与树结构

- 核心是记住人的工作：想实现什么、改过哪些要求、哪些已经完成、哪些仍悬着。
- 按父任务与子任务组织；一项用一两句概括人的需求、决定和当前状态。
- 尚未动工的想法标为“🫐 待展开”；做到一半的事简记实际停留位置，需要时补一句停下原因。
- Agent 提议经用户采纳后进入任务树。询问技术可记“🍎 已讨论”，讨论本身不等于决定安装或开发。
- 实现结果仅用于交代进度；需要用户判断效果时保留产物入口，标为“🍊 待确认”。
- 脚本、环境、命令、测试与执行过程由 task 的 docs 承接。

原文轮次使用 `../../prompts.md#pN`；产物与 task 文档按实际位置链接。

需要对照实际写法时，阅读 [具体例子](examples/dev.md)。
