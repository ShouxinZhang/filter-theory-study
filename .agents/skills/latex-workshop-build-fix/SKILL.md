# LaTeX Workshop 构建排障

遵循项目 AGENTS.md 与 [coding.md](../../prompts/coding.md)，保护用户正在编辑的 TeX 内容。

- 在任务目录保留简短的打勾计划和排障日志，技能正文不堆放单次故障记录。
- 弹窗只是失败摘要，先读 LaTeX Workshop 的 Output 与最新编译日志，定位第一条致命错误。
- 同时记录日志时间，日志首行的实际引擎，编译入口，工作目录和输出目录，避免误读旧日志。
- 用 `rg` 检查导言区，文件头魔法注释，工作区 settings.json，构建脚本和局部 latexmkrc。
- `fontspec` 与 `xeCJK` 项目通常需要 XeLaTeX；若日志显示 pdfTeX，先修正引擎选择，不删除字体包绕过错误。
- LaTeX Workshop 的默认或上次使用配方不一定等于终端构建命令；主文件的配方注释也未必覆盖独立子文件。
- 核对配方名称与配置名称完全一致，检查所用 latexmk 工具实际包含的引擎参数。
- 对 subfiles 项目区分独立编译入口与主文档入口，不盲目将所有子文件的 root 指向主文档。
- 先复现编辑器实际调用，再与项目成功构建脚本对照，优先修正最小范围的项目配置。
- 工作区配置只改相关键，局部 latexmkrc 只约束对应 TeX 项目，不覆盖用户全局偏好。
- 统一编辑器，脚本和 PDF 查看器的输出位置，防止编译成功后仍展示旧 PDF。
- 修复首个错误后重新读日志；后续错误可能此前被掩盖，不能把换引擎当作全部修复。
- 若出现文件结尾处的 Emergency stop，检查缺失的 `\end{document}` 与环境或括号配对，保留用户正文。
- 修复后先正常重建；仅在确认缓存阻止重试时定向清理生成物或强制重建，保留源码和日志证据。
- 分别验证主文档与受影响的独立子文档，检查退出码，新日志引擎，新 PDF 时间及未定义引用。
- 终端验证应复用编辑器的工具参数，不能仅凭另一套脚本成功便宣称编辑器路径已验证。
- 若无法实际操作编辑器，明确说明已验证的等价命令与仍需用户触发的 UI 行为。
- 把根因，修改文件和验证结果写入任务日志；审阅技能，删除未经证实的推测与无关规则。
